Допустим, вы создаёте в цикле `for` несколько разных `lambda` (или обычных функций):

```python
>>> squares = []
>>> for x in range(5):
...     squares.append(lambda: x**2)
```

Получается список из 5 функций, каждая считает `x**2`. Можно ожидать, что они вернут `0`, `1`, `4`, `9` и `16`. Но на деле все возвращают `16`:

```python
>>> squares[2]()
16
>>> squares[4]()
16
```

Причина: `x` — не локальная переменная `lambda`. Она определена во внешней области видимости. Функция читает `x` в момент **вызова**, а не в момент создания. После цикла `x` равен `4`, поэтому все функции возвращают `4**2`, то есть `16`.

Это легко проверить. Измените `x` и посмотрите, как изменится результат:

```python
>>> x = 8
>>> squares[2]()
64
```

Чтобы этого избежать, сохраните значение в локальной переменной `lambda`. Тогда функция не зависит от глобального `x`:

```python
>>> squares = []
>>> for x in range(5):
...     squares.append(lambda n=x: n**2)
```

Здесь `n=x` создаёт локальную для `lambda` переменную `n`. Её значение вычисляется при создании `lambda`, то есть равно `x` на этом шаге цикла. В первой `lambda` `n` равно `0`, во второй — `1`, в третьей — `2` и так далее. Теперь каждая функция возвращает верный результат:

```python
>>> squares[2]()
4
>>> squares[4]()
16
```

Это поведение не особенность `lambda`. Обычные функции (`def`) ведут себя так же.
