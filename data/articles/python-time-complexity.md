Эта страница описывает временную сложность («O большое») операций в текущем CPython. Другие реализации Python (а также старые или ещё не выпущенные версии CPython) могут работать немного иначе. Обычно можно считать, что они медленнее не больше чем в O(log n) раз.

Обозначения: **n** — число элементов в контейнере сейчас. **k** — значение параметра или число элементов в параметре.

## list

Средний случай предполагает, что параметры выбраны равномерно случайно.

Внутри список — это массив. Самые дорогие операции:

- рост больше текущего выделенного размера — нужно переносить все элементы;
- вставка или удаление близко к началу — нужно сдвигать все элементы после этого места.

Если нужно добавлять и удалять с обоих концов, возьмите `collections.deque`.

| Операция | Средний случай | Амортизированный худший случай |
|---|---|---|
| Копия | O(n) | O(n) |
| Append [1] | O(1) | O(1) |
| Pop последнего | O(1) | O(1) |
| Pop из середины [2] | O(n) | O(n) |
| Insert | O(n) | O(n) |
| Чтение по индексу | O(1) | O(1) |
| Запись по индексу | O(1) | O(1) |
| Удаление элемента | O(n) | O(n) |
| Перебор | O(n) | O(n) |
| Чтение среза | O(k) | O(k) |
| Удаление среза | O(n) | O(n) |
| Запись в срез | O(k+n) | O(k+n) |
| Extend [1] | O(k) | O(k) |
| Сортировка | O(n log n) | O(n log n) |
| Умножение на k | O(nk) | O(nk) |
| `x in s` | O(n) | |
| `min(s)`, `max(s)` | O(n) | |
| Длина | O(1) | O(1) |

## collections.deque

Deque (двусторонняя очередь) внутри — двусвязный список. Точнее, список массивов, а не отдельных объектов: так эффективнее. Оба конца доступны быстро. Но даже чтение из середины медленное, а вставка и удаление в середине — ещё медленнее.

| Операция | Средний случай | Амортизированный худший случай |
|---|---|---|
| Копия | O(n) | O(n) |
| `append` | O(1) | O(1) |
| `appendleft` | O(1) | O(1) |
| `pop` | O(1) | O(1) |
| `popleft` | O(1) | O(1) |
| `extend` | O(k) | O(k) |
| `extendleft` | O(k) | O(k) |
| `rotate` | O(k) | O(k) |
| `remove` | O(n) | O(n) |
| Длина | O(1) | O(1) |

## set

См. `dict`: реализация намеренно очень похожа.

| Операция | Средний случай | Худший случай | Примечание |
|---|---|---|---|
| `x in s` | O(1) | O(n) | |
| Объединение `s \| t` | O(len(s)+len(t)) | | |
| Пересечение `s & t` | O(min(len(s), len(t))) | O(len(s) · len(t)) | если `t` не множество, замените min на max |
| Пересечение многих `s1 & s2 & … & sn` | | (n−1)·O(l), где l — max(len(s1), …, len(sn)) | |
| Разность `s - t` | O(len(s)) | | |
| `s.difference_update(t)` | O(len(t)) | | |
| Симметрическая разность `s ^ t` | O(len(s)) | O(len(s) · len(t)) | |
| `s.symmetric_difference_update(t)` | O(len(t)) | O(len(t) · len(s)) | |

- Сложность у разности `s - t` (или `s.difference(t)`) и у разности на месте `s.difference_update(t)` **разная**. Первая — O(len(s)): каждый элемент `s` добавляется в новое множество, если его нет в `t`. Вторая — O(len(t)): каждый элемент `t` удаляется из `s`. Выбирайте с учётом того, какое множество длиннее и нужно ли новое множество.
- Для операторов вроде `s - t` оба операнда должны быть множествами. Методы работают с любым итерируемым `t`, например `s.difference(l)`, где `l` — список.

## dict

Средний случай для `dict` предполагает, что хэш-функция ключей хорошая и коллизии редки. Ещё он предполагает, что ключи в параметрах выбраны равномерно случайно из всех ключей.

У словарей, где на практике только строковые ключи, есть быстрый путь. Он не меняет алгоритмическую сложность, но сильно влияет на константы, то есть на реальное время работы программы.

| Операция | Средний случай | Амортизированный худший случай |
|---|---|---|
| `k in d` | O(1) | O(n) |
| Копия [3] | O(n) | O(n) |
| Чтение по ключу | O(1) | O(n) |
| Запись по ключу [1] | O(1) | O(n) |
| Удаление по ключу | O(1) | O(n) |
| Перебор [3] | O(n) | O(n) |

## Примечания

[1] Эти операции опираются на слово «амортизированный» в «амортизированном худшем случае». Отдельная операция может занять неожиданно много времени: это зависит от истории контейнера.

[2] Удаление элемента с индексом **k** из списка длины **n** сдвигает все элементы *после* **k** на одну позицию влево (через `memmove`). Нужно сдвинуть **n − k** элементов, поэтому операция стоит **O(n − k)**. Лучший случай — удалить предпоследний элемент: один сдвиг. Худший — удалить первый: **n − 1** сдвигов. В среднем удаляется элемент из середины: **O(n/2) = O(n)** операций.

[3] Для этих операций **n** в худшем случае — максимальный размер, которого контейнер когда-либо достигал, а не текущий размер. Например, в словарь добавили N объектов, потом удалили N − 1. Словарь всё равно рассчитан на N объектов (как минимум), пока не будет новой вставки.
