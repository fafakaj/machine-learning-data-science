Чтобы обучить модель на 4 млрд параметров в смешанной точности с размером батча 16, нужно примерно 85 ГБ памяти GPU. Если понимать, что занимает память и какие операции идут при обучении, проще найти, где память можно сэкономить.

```text
┌─────────────────────────── ТЕНЗОРЫ ──────────────────────────────────┐
│                                                                      │
│  ВЕСА МОДЕЛИ         ████████████████████████  6 байт/параметр       │
│  (смешанная точн.)   ├── копия fp16 (2 Б) — прямой/обратный проход   │
│                      └── копия fp32 (4 Б) — стабильное обновление    │
│                                                                      │
│  СОСТОЯНИЯ           ████████████████████████████████  8 байт/парам. │
│  ОПТИМИЗАТОРА (Adam) ├── момент fp32  (4 Б)                          │
│                      └── дисперсия fp32 (4 Б)                        │
│                      ↳ квантованный Adam (bitsandbytes) → 2 байта    │
│                                                                      │
│  ГРАДИЕНТЫ           ████████████████  4 байта/параметр (fp32)       │
│                      └── считаются при обратном проходе              │
│                                                                      │
│  АКТИВАЦИИ           ████ зависит от батч × длина × глубина × ширина │
│  (кэш прямого прох.) └── хранятся для обратного прохода; память      │
│                          может кончиться, даже если модель влезла    │
│                          (длинные последовательности, большой батч); │
│                          bf16/fp16 при смешанной точности            │
│                                                                      │
│  ВРЕМЕННЫЕ ТЕНЗОРЫ   ▓ живут недолго (softmax, буферы matmul)        │
│                      └── пики могут вызвать нехватку памяти (OOM)    │
│                                                                      │
│  ПРОЧЕЕ              ▒ кэши beam search, большие таблицы эмбеддингов │
└──────────────────────────────────────────────────────────────────────┘
```

В памяти GPU два вида содержимого: хранимые тензоры и операции, которые их обрабатывают.

## Тензоры

При обучении нужно хранить много видов тензоров.

- **Веса модели** лежат на GPU. При обучении в смешанной точности нужны две копии весов: в fp16 для прямого и обратного прохода и в fp32 как «главная копия» для стабильного обновления весов. Итого 6 байт на параметр.
- **Состояния оптимизатора.** Adam хранит на каждый параметр два дополнительных тензора — момент и дисперсию, оба в fp32. Это ещё 8 байт на параметр. Квантованная версия Adam из [bitsandbytes](https://huggingface.co/docs/bitsandbytes/main/en/index) сжимает их до 2 байт на параметр.
- **Градиенты** считаются для каждого параметра при обратном проходе. Они хранятся в fp32 — 4 байта на параметр.
- **Активации прямого прохода** считаются при прямом проходе и хранятся для обратного, чтобы посчитать градиенты. Их размер зависит от размера батча, длины последовательности, глубины модели и ширины скрытого слоя. Поэтому размер батча или длина последовательности могут исчерпать память GPU, даже если сама модель помещается.
- **Временные тензоры** создают операции вроде softmax и умножения матриц. Они освобождаются после операции. Если одна операция требует очень много памяти, возникает временный пик, и память может закончиться.
- **Прочие расходы.** Некоторые функции добавляют свои расходы. Например, beam search хранит несколько вариантов выхода, а таблицы эмбеддингов для больших словарей бывают очень большими.

> Итого без активаций: 6 + 8 + 4 = 18 байт на параметр. Для модели на 1 млрд параметров это около 18 ГБ ещё до активаций. *(Пример добавлен при переводе.)*

## Операции

При обучении есть три основных вида операций.

- **Умножения матриц** (matmul) — основной вид. Это линейные слои, проекции Q, K, V, выходная проекция внимания и слои FFN. Больше всего памяти здесь занимают матрицы оценок внимания: они растут как квадрат длины последовательности. Поэтому длинные последовательности так дороги, и существуют разные реализации внимания, которые не держат всю матрицу в памяти целиком.
- **Операции свёртки (reduction)**, например softmax и layer norm. Они читают весь тензор, считают статистику по одному измерению, а потом читают тензор снова, чтобы её применить. За одну операцию к памяти обращаются несколько раз.
- **Поэлементные операции**, например функции активации и dropout. Они применяют функцию к каждому элементу отдельно. Память пропорциональна размеру тензора.

## Что дальше

- [Gradient accumulation](https://huggingface.co/docs/transformers/grad_accumulation) — как обучать с большим эффективным размером батча без нехватки памяти.
- [Gradient checkpointing](https://huggingface.co/docs/transformers/grad_checkpointing) — как экономить память, храня только часть активаций (есть перевод в этой же теме плана).
