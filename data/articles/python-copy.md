Присваивание в Python не копирует объект. Оно связывает имя с объектом. Иногда нужна копия коллекции: изменяемой или с изменяемыми элементами. Тогда одну копию можно менять, а другая останется прежней. Модуль `copy` даёт общие операции поверхностного и глубокого копирования.

## Функции модуля

- `copy.copy(obj)` — вернуть поверхностную копию `obj`.
- `copy.deepcopy(obj[, memo])` — вернуть глубокую копию `obj`.
- `copy.replace(obj, /, **changes)` — создать новый объект того же типа, что `obj`, и заменить в нём поля значениями из `changes`. Добавлена в Python 3.13.
- исключение `copy.Error` — ошибка этого модуля.

## Поверхностная и глубокая копия

Разница важна только для составных объектов. Это объекты, которые содержат другие объекты: списки, экземпляры классов.

- **Поверхностная копия** создаёт новый составной объект. Потом она вставляет в него **ссылки** на объекты оригинала (там, где это возможно).
- **Глубокая копия** создаёт новый составной объект. Потом она рекурсивно вставляет в него **копии** объектов оригинала.

```python
import copy

a = [[1, 2], [3]]
shallow = copy.copy(a)
deep = copy.deepcopy(a)

a[0].append(99)
print(shallow)  # [[1, 2, 99], [3]] — внутренний список общий
print(deep)     # [[1, 2], [3]]     — внутренний список скопирован
```

*(Пример добавлен при переводе.)*

## Две проблемы глубокого копирования

У глубокой копии есть две проблемы. У поверхностной их нет.

- Рекурсивные объекты могут дать бесконечный цикл. Рекурсивный объект прямо или через другие объекты содержит ссылку на себя.
- Глубокая копия копирует всё. Поэтому она может скопировать лишнее, например данные, которые копии должны делить.

Функция `deepcopy()` решает эти проблемы так:

- хранит словарь `memo` с объектами, которые уже скопированы в этом проходе;
- разрешает своим классам переопределить копирование или набор копируемых частей.

## Что модуль не копирует

Модуль не копирует модули, методы, трассировки стека, кадры стека, файлы, сокеты, окна и похожие типы. Функции и классы он «копирует» (поверхностно и глубоко) так: возвращает исходный объект без изменений. Так же с ними работает модуль `pickle`.

## Копия без модуля copy

Поверхностную копию многих коллекций делает их метод `copy()`: `list.copy()`, `dict.copy()`, `set.copy()`. Последовательность (список, `bytearray`) можно скопировать срезом целиком: `sequence[:]`.

Но эти методы и срез для экземпляра подкласса могут вернуть экземпляр базового типа. А `copy.copy()` обычно возвращает экземпляр того же типа.

## Своё копирование в классе

Класс управляет копированием через те же интерфейсы, что и сериализацией (`pickle`). Модуль `copy` использует функции, зарегистрированные в модуле `copyreg`.

Чтобы задать своё копирование, определите в классе специальные методы:

- `object.__copy__(self)` — вызывается при поверхностном копировании. Аргументов, кроме `self`, нет.
- `object.__deepcopy__(self, memo)` — вызывается при глубоком копировании. Получает словарь `memo`. Если методу нужна глубокая копия части объекта, он вызывает `deepcopy(часть, memo)`. Словарь `memo` считайте «чёрным ящиком»: не читайте и не меняйте его сами.

Функция `copy.replace()` умеет меньше, чем `copy()` и `deepcopy()`. Она работает только с именованными кортежами из `namedtuple()`, с `dataclasses` и с классами, где есть метод `__replace__()`.

- `object.__replace__(self, /, **changes)` — создаёт новый объект того же типа и заменяет поля значениями из `changes`. Добавлен в Python 3.13.
