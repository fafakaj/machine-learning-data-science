## Урок 1. Основы SELECT

[Урок на SQLBolt](https://sqlbolt.com/lesson/select_queries_introduction)

Данные из базы получают запросом `SELECT`. Запрос описывает три вещи: какие данные нужны, где они лежат и (по желанию) как их преобразовать перед выдачей.

Таблицу удобно представлять так:

- таблица — вид сущности, например «собаки»;
- строка — один конкретный экземпляр, например «мопс»;
- столбец — свойство, общее для всех экземпляров, например «цвет шерсти».

Самый простой запрос выбирает несколько столбцов из всех строк:

```sql
SELECT column, another_column, …
FROM mytable;
```

Результат — таблица из строк и столбцов: копия исходной таблицы, но только с запрошенными столбцами.

Чтобы получить все столбцы, вместо списка имён пишут звёздочку:

```sql
SELECT *
FROM mytable;
```

Так удобно быстро посмотреть, что лежит в таблице.

## Урок 2. Условия WHERE (часть 1): числа

[Урок на SQLBolt](https://sqlbolt.com/lesson/select_queries_with_constraints)

В таблице может быть сто миллионов строк. Читать их все неудобно и долго. Чтобы отобрать нужные строки, в запрос добавляют `WHERE`. Условие проверяется для каждой строки: строка попадает в результат, только если условие истинно.

```sql
SELECT column, another_column, …
FROM mytable
WHERE condition
  AND/OR another_condition
  AND/OR …;
```

Сложные условия собирают из нескольких частей через `AND` и `OR`, например `num_wheels >= 4 AND doors <= 2`.

Операторы для чисел (целых и дробных):

| Оператор | Условие | Пример |
|---|---|---|
| `=`, `!=`, `<`, `<=`, `>`, `>=` | обычное сравнение | `col_name != 4` |
| `BETWEEN … AND …` | число в диапазоне, границы включены | `col_name BETWEEN 1.5 AND 10.5` |
| `NOT BETWEEN … AND …` | число вне диапазона (границы включены в диапазон) | `col_name NOT BETWEEN 1 AND 10` |
| `IN (…)` | число есть в списке | `col_name IN (2, 4, 6)` |
| `NOT IN (…)` | числа нет в списке | `col_name NOT IN (1, 3, 5)` |

Условие не только делает результат понятнее. Запрос ещё и работает быстрее: база возвращает меньше лишних данных.

> Ключевые слова SQL не обязательно писать заглавными буквами. Но так принято: заглавные слова легко отличить от имён столбцов и таблиц, и запрос читается проще.

## Урок 3. Условия WHERE (часть 2): строки

[Урок на SQLBolt](https://sqlbolt.com/lesson/select_queries_with_constraints_pt_2)

Для столбцов с текстом в `WHERE` есть свои операторы: сравнение без учёта регистра и поиск по шаблону.

| Оператор | Условие | Пример |
|---|---|---|
| `=` | точное совпадение строки с учётом регистра (один знак `=`) | `col_name = "abc"` |
| `!=` или `<>` | точное несовпадение с учётом регистра | `col_name != "abcd"` |
| `LIKE` | совпадение без учёта регистра | `col_name LIKE "ABC"` |
| `NOT LIKE` | несовпадение без учёта регистра | `col_name NOT LIKE "ABCD"` |
| `%` | в шаблоне `LIKE` / `NOT LIKE`: любая последовательность из нуля или больше символов | `col_name LIKE "%AT%"` — подходят "AT", "ATTIC", "CAT", "BATS" |
| `_` | в шаблоне `LIKE` / `NOT LIKE`: ровно один любой символ | `col_name LIKE "AN_"` — подходит "AND", но не "AN" |
| `IN (…)` | строка есть в списке | `col_name IN ("A", "B", "C")` |
| `NOT IN (…)` | строки нет в списке | `col_name NOT IN ("D", "E", "F")` |

Строки всегда пишут в кавычках. Иначе база не отличит слова строки от ключевых слов SQL.

Большинство баз выполняют эти операторы быстро. Но для полнотекстового поиска лучше специальные библиотеки, например Apache Lucene или Sphinx. Они умеют больше: учитывают языки и сложные запросы.

## Урок 4. Уникальные значения, сортировка, LIMIT и OFFSET

[Урок на SQLBolt](https://sqlbolt.com/lesson/filtering_sorting_query_results)

Строки в таблице могут быть уникальными, а результат запроса — нет. Например, в один год вышло несколько фильмов. Чтобы убрать строки-повторы, пишут `DISTINCT`:

```sql
SELECT DISTINCT column, another_column, …
FROM mytable
WHERE condition(s);
```

`DISTINCT` убирает полностью одинаковые строки результата. Как убирать повторы по отдельным столбцам, покажет урок про `GROUP BY`.

В реальных базах строки лежат в произвольном порядке. Когда строк тысячи или миллионы, читать результат трудно. Поэтому результат сортируют по столбцу через `ORDER BY`: по возрастанию (`ASC`) или по убыванию (`DESC`):

```sql
SELECT column, another_column, …
FROM mytable
WHERE condition(s)
ORDER BY column ASC/DESC;
```

Строки сортируются по значению столбца: числа по величине, текст по алфавиту. Некоторые базы позволяют задать правила сравнения (collation), чтобы правильно сортировать текст на разных языках.

С `ORDER BY` часто используют `LIMIT` и `OFFSET`:

- `LIMIT` ограничивает число строк результата;
- `OFFSET` (не обязательно) говорит, сколько строк пропустить с начала.

```sql
SELECT column, another_column, …
FROM mytable
WHERE condition(s)
ORDER BY column ASC/DESC
LIMIT num_limit OFFSET num_offset;
```

Пример из жизни — лента сайта: первая страница — первые 10 записей по популярности, вторая — следующие 10 (`LIMIT 10 OFFSET 10`). База обрабатывает и отдаёт только нужную часть, поэтому работает быстрее.

> `LIMIT` и `OFFSET` обычно применяются последними, после всех остальных частей запроса. Порядок выполнения запроса разобран в 12-м уроке SQLBolt.

## Урок 6. Запросы к нескольким таблицам: JOIN

[Урок на SQLBolt](https://sqlbolt.com/lesson/select_queries_with_joins)

В реальных базах данные об одной сущности часто разложены по нескольким таблицам. Этот приём называют **нормализацией**.

Нормализация полезна:

- в каждой таблице меньше повторов данных;
- данные разных таблиц растут независимо (например, виды двигателей добавляются отдельно от моделей машин).

Цена — запросы сложнее: данные нужно собрать из разных частей базы. А на многих больших таблицах могут быть проблемы со скоростью.

Таблицы с данными об одной сущности связывает **первичный ключ** (primary key). Он *однозначно* определяет сущность во всей базе. Часто это целое число с автоувеличением (экономит место), но подойдёт и строка, и хэш — лишь бы значение было уникальным.

`JOIN` объединяет строки двух таблиц по такому ключу. Первый вид объединения — `INNER JOIN`:

```sql
SELECT column, another_table_column, …
FROM mytable
INNER JOIN another_table
    ON mytable.id = another_table.id
WHERE condition(s)
ORDER BY column, … ASC/DESC
LIMIT num_limit OFFSET num_offset;
```

`INNER JOIN` находит пары строк из первой и второй таблицы с одинаковым ключом (условие в `ON`) и склеивает их в одну строку со столбцами обеих таблиц. Остальные части запроса (`WHERE`, `ORDER BY`, `LIMIT`) применяются уже после объединения.

> Часто пишут просто `JOIN` — это то же самое, что `INNER JOIN`. Но полное имя удобнее, когда в запросе появятся другие виды объединения (следующий урок SQLBolt).
