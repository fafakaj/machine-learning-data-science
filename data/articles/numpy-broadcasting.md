Broadcasting (транслирование) — это правила, по которым NumPy работает с массивами разной формы в арифметических операциях. При некоторых условиях меньший массив «растягивается» по большему, чтобы формы стали совместимы.

Broadcasting векторизует операции над массивами: цикл идёт в C, а не в Python. При этом NumPy не делает лишних копий данных, и алгоритм обычно получается эффективным. Но иногда broadcasting — плохая идея: он тратит слишком много памяти, и вычисления замедляются.

Обычно операции NumPy идут поэлементно над парой массивов. В простейшем случае массивы должны иметь одинаковую форму:

```python
>>> import numpy as np
>>> a = np.array([1.0, 2.0, 3.0])
>>> b = np.array([2.0, 2.0, 2.0])
>>> a * b
array([2.,  4.,  6.])
```

Правило broadcasting ослабляет это требование, если формы массивов удовлетворяют некоторым условиям. Простейший пример — операция над массивом и скаляром:

```python
>>> import numpy as np
>>> a = np.array([1.0, 2.0, 3.0])
>>> b = 2.0
>>> a * b
array([2.,  4.,  6.])
```

Результат тот же, что в первом примере, где `b` был массивом. Можно представить, что скаляр `b` во время операции *растягивается* в массив формы `a`. Новые элементы `b` — просто копии исходного скаляра.

Растягивание — только образ. NumPy достаточно умён и использует исходный скаляр без настоящих копий. Поэтому broadcasting экономит и память, и вычисления.

Второй пример эффективнее первого: при умножении переносится меньше памяти (`b` — скаляр, а не массив).

## Общие правила

При операции над двумя массивами NumPy сравнивает их формы поэлементно. Он начинает с последнего (самого правого) измерения и идёт влево. Два измерения совместимы, если:

1. они равны, или
2. одно из них равно 1.

Если условия не выполнены, NumPy бросает исключение `ValueError: operands could not be broadcast together`: формы массивов несовместимы.

У входных массивов может быть разное *число* измерений. У результата столько измерений, сколько у самого «многомерного» входа. *Размер* каждого измерения результата — наибольший из размеров этого измерения у входов. Недостающие измерения считаются равными 1.

Пример: есть массив RGB-значений формы `256×256×3`. Нужно умножить каждый цвет картинки на свой коэффициент. Для этого картинку умножают на одномерный массив из 3 значений. Выровняем размеры по последним осям — они совместимы:

```text
Картинка   (3d массив): 256 x 256 x 3
Множители  (1d массив):             3
Результат  (3d массив): 256 x 256 x 3
```

Если одно из сравниваемых измерений равно 1, берётся другое. Иначе говоря, измерения размера 1 растягиваются («копируются») до размера другого.

В следующем примере у обоих массивов `A` и `B` есть оси длины 1. При broadcasting они расширяются до большего размера:

```text
A         (4d массив):  8 x 1 x 6 x 1
B         (3d массив):      7 x 1 x 5
Результат (4d массив):  8 x 7 x 6 x 5
```

## Массивы, совместимые по broadcasting

Набор массивов называют совместимым по broadcasting (broadcastable) к одной форме, если правила выше дают корректный результат.

Например, пусть `a.shape` равна (5, 1), `b.shape` — (1, 6), `c.shape` — (6,), а `d.shape` — (), то есть `d` — скаляр. Тогда `a`, `b`, `c` и `d` приводятся к форме (5, 6):

- `a` ведёт себя как массив (5, 6), где столбец `a[:, 0]` повторён во всех столбцах;
- `b` ведёт себя как массив (5, 6), где строка `b[0, :]` повторена во всех строках;
- `c` ведёт себя как массив (1, 6), а значит, как массив (5, 6), где `c[:]` повторён в каждой строке;
- `d` ведёт себя как массив (5, 6), где одно значение повторено везде.

Ещё примеры:

```text
A         (2d массив):  5 x 4
B         (1d массив):      1
Результат (2d массив):  5 x 4

A         (2d массив):  5 x 4
B         (1d массив):      4
Результат (2d массив):  5 x 4

A         (3d массив):  15 x 3 x 5
B         (3d массив):  15 x 1 x 5
Результат (3d массив):  15 x 3 x 5

A         (3d массив):  15 x 3 x 5
B         (2d массив):       3 x 5
Результат (3d массив):  15 x 3 x 5

A         (3d массив):  15 x 3 x 5
B         (2d массив):       3 x 1
Результат (3d массив):  15 x 3 x 5
```

Примеры форм, которые **не** совместимы:

```text
A  (1d массив):  3
B  (1d массив):  4         # последние измерения не совпадают

A  (2d массив):      2 x 1
B  (3d массив):  8 x 4 x 3 # не совпадают предпоследние измерения
```

Пример: одномерный массив прибавляется к двумерному:

```python
>>> import numpy as np
>>> a = np.array([[ 0.0,  0.0,  0.0],
...               [10.0, 10.0, 10.0],
...               [20.0, 20.0, 20.0],
...               [30.0, 30.0, 30.0]])
>>> b = np.array([1.0, 2.0, 3.0])
>>> a + b
array([[  1.,   2.,   3.],
       [ 11.,  12.,  13.],
       [ 21.,  22.,  23.],
       [ 31.,  32.,  33.]])
>>> b = np.array([1.0, 2.0, 3.0, 4.0])
>>> a + b
Traceback (most recent call last):
ValueError: operands could not be broadcast together with shapes (4,3) (4,)
```

В первом случае `b` прибавляется к каждой строке `a`. Во втором — исключение: формы (4, 3) и (4,) несовместимы (сравниваются последние измерения 3 и 4).

Broadcasting даёт удобный способ взять внешнее произведение (или любую другую «внешнюю» операцию) двух массивов. Пример внешнего сложения двух одномерных массивов:

```python
>>> import numpy as np
>>> a = np.array([0.0, 10.0, 20.0, 30.0])
>>> b = np.array([1.0, 2.0, 3.0])
>>> a[:, np.newaxis] + b
array([[ 1.,   2.,   3.],
       [11.,  12.,  13.],
       [21.,  22.,  23.],
       [31.,  32.,  33.]])
```

Индекс `np.newaxis` добавляет в `a` новую ось. Получается двумерный массив `4×1`. Массив `4×1` вместе с `b` формы `(3,)` даёт массив `4×3`.

## Практический пример: векторное квантование

Broadcasting часто встречается в реальных задачах. Типичный пример — алгоритм векторного квантования (VQ) в теории информации, классификации и близких областях.

Основная операция VQ: найти в наборе точек (их называют `codes`) ближайшую к данной точке (её называют `observation`). В простом двумерном примере ниже `observation` — вес и рост спортсмена, которого нужно классифицировать. `codes` — разные классы спортсменов.

Чтобы найти ближайшую точку, нужно посчитать расстояние от наблюдения до каждого кода. Наименьшее расстояние даёт лучшее совпадение. Здесь ближе всего `codes[0]`: спортсмен, скорее всего, баскетболист.

```python
>>> from numpy import array, argmin, sqrt, sum
>>> observation = array([111.0, 188.0])
>>> codes = array([[102.0, 203.0],
...                [132.0, 193.0],
...                [45.0, 155.0],
...                [57.0, 173.0]])
>>> diff = codes - observation    # здесь работает broadcasting
>>> dist = sqrt(sum(diff**2, axis=-1))
>>> argmin(dist)
0
```

Массив `observation` растягивается до формы `codes`:

```text
Observation  (1d массив):      2
Codes        (2d массив):  4 x 2
Diff         (2d массив):  4 x 2
```

Обычно с набором `codes` сравнивают много наблюдений, например из базы данных. Такой сценарий:

```text
Observation  (2d массив):      10 x 3
Codes        (3d массив):   5 x 1 x 3
Diff         (3d массив):  5 x 10 x 3
```

Трёхмерный массив `diff` — следствие broadcasting, а не необходимость алгоритма. На больших данных получится огромный промежуточный массив, и вычисления будут неэффективны. Если же считать каждое наблюдение отдельно, в цикле Python вокруг двумерного кода выше, массивы будут намного меньше.

Broadcasting — сильный инструмент. С ним код короткий, обычно понятный и очень быстро считает в C. Но иногда для конкретного алгоритма broadcasting тратит слишком много памяти. Тогда лучше написать внешний цикл алгоритма на Python. Код может стать и понятнее: чем больше измерений в broadcasting, тем труднее его читать.
