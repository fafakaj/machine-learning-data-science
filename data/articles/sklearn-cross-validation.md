## Зачем кросс-валидация

Обучать функцию предсказания и проверять её на одних и тех же данных — методологическая ошибка. Модель, которая просто повторяет метки уже виденных примеров, получит идеальный результат. Но на новых данных она ничего полезного не предскажет. Это называют **переобучением** (overfitting).

Чтобы этого избежать, в эксперименте машинного обучения с учителем часть данных откладывают как **тестовую выборку** `X_test, y_test`. Слово «эксперимент» не значит «только в науке»: и в бизнесе машинное обучение обычно начинается с экспериментов. Лучшие гиперпараметры подбирают, например, поиском по сетке (grid search).

В scikit-learn случайное разбиение на обучающую и тестовую выборки делает функция `train_test_split`. Загрузим набор iris и обучим на нём линейный SVM:

```python
>>> import numpy as np
>>> from sklearn.model_selection import train_test_split
>>> from sklearn import datasets
>>> from sklearn import svm
>>> X, y = datasets.load_iris(return_X_y=True)
>>> X.shape, y.shape
((150, 4), (150,))
```

Отложим 40 % данных для проверки классификатора:

```python
>>> X_train, X_test, y_train, y_test = train_test_split(
...     X, y, test_size=0.4, random_state=0)
>>> X_train.shape, y_train.shape
((90, 4), (90,))
>>> X_test.shape, y_test.shape
((60, 4), (60,))
>>> clf = svm.SVC(kernel='linear', C=1).fit(X_train, y_train)
>>> clf.score(X_test, y_test)
0.96
```

Когда перебирают настройки модели (гиперпараметры), например `C` у SVM, остаётся риск переобучиться *на тестовой выборке*. Параметры можно подкручивать, пока результат на тесте не станет лучшим. Так знание о тестовой выборке «утекает» в модель, и метрика больше не показывает качество на новых данных.

Решение — отложить ещё одну часть данных, **валидационную выборку**. Модель обучают на обучающей выборке, оценивают на валидационной, а когда эксперимент выглядит успешным, делают финальную оценку на тестовой.

Но три части сильно уменьшают число примеров для обучения. А результат может зависеть от того, как случайно разбились обучающая и валидационная выборки.

Решение этой проблемы — **кросс-валидация** (cross-validation, CV). Тестовую выборку для финальной оценки всё равно откладывают, но отдельная валидационная выборка уже не нужна.

В базовом подходе, *k-fold CV*, обучающую выборку делят на *k* частей (фолдов). Для каждого из *k* фолдов:

- модель обучают на остальных k − 1 фолдах;
- обученную модель проверяют на этом фолде: считают метрику, например accuracy.

Итоговая метрика k-fold — среднее значений из цикла. Подход может быть дорогим по вычислениям. Зато он не тратит данные впустую, как фиксированная валидационная выборка. Это большое преимущество, когда примеров очень мало.

## Независимые одинаково распределённые данные

Данные называют независимыми и одинаково распределёнными (i.i.d.), если все примеры получены одним процессом и процесс «не помнит» прошлых примеров. Для таких данных подходят разбиения ниже.

> Примечание. Предположение i.i.d. популярно в теории, но на практике редко выполняется. Если примеры зависят от времени, надёжнее кросс-валидация для временных рядов (`TimeSeriesSplit`). Если у данных есть группы (примеры от разных людей, экспериментов, приборов), надёжнее групповая кросс-валидация (`GroupKFold`).

## K-fold

`KFold` делит все примеры на *k* групп одинакового размера (если возможно). Группы называют фолдами. Если k = n (число примеров), это стратегия Leave One Out. Модель обучается на k − 1 фолдах, а оставшийся фолд служит тестом.

Пример 2-fold кросс-валидации на наборе из 4 примеров:

```python
>>> import numpy as np
>>> from sklearn.model_selection import KFold
>>> X = ["a", "b", "c", "d"]
>>> kf = KFold(n_splits=2)
>>> for train, test in kf.split(X):
...     print("%s %s" % (train, test))
[2 3] [0 1]
[0 1] [2 3]
```

`KFold` не учитывает ни классы, ни группы.

Каждое разбиение — это два массива индексов: первый для *обучающей* выборки, второй для *тестовой*. Выборки получают индексацией numpy:

```python
>>> X = np.array([[0., 0.], [1., 1.], [-1., -1.], [2., 2.]])
>>> y = np.array([0, 1, 0, 1])
>>> X_train, X_test, y_train, y_test = X[train], X[test], y[train], y[test]
```

## Стратификация по классам

В некоторых задачах классификации есть редкие классы. Например, отрицательных примеров может быть на порядки больше, чем положительных: медицинский скрининг, поиск мошенничества.

Тогда при разбиении может получиться обучающий или валидационный фолд без примеров какого-то класса. Обычно это приводит к проблемам:

- метрика не определена (например, ROC AUC);
- `fit` бросает исключение;
- у многоклассовых моделей, обученных на разных фолдах, в выходе `predict_proba` или `decision_function` не хватает столбцов.

Чтобы этого избежать, `StratifiedKFold` и `StratifiedShuffleSplit` используют стратифицированную выборку: в каждом фолде доли классов примерно такие же, как во всех данных.

> Примечание. Стратификацию добавили в scikit-learn, чтобы обойти инженерные проблемы выше, а не чтобы решить статистическую задачу. Стратификация делает фолды более однородными и поэтому скрывает часть естественного разброса при обучении на малом числе примеров. В результате разброс метрики между фолдами может искусственно уменьшиться: он уже не отражает настоящую неопределённость качества классификатора при редких классах.

### Stratified K-fold

`StratifiedKFold` — вариант *K-fold*, который возвращает *стратифицированные* фолды: в каждом примерно тот же процент примеров каждого класса, что и во всех данных.

Пример стратифицированной 3-fold кросс-валидации на 50 примерах двух несбалансированных классов (45 и 5). Выведем число примеров каждого класса и сравним с `KFold`:

```python
>>> from sklearn.model_selection import StratifiedKFold, KFold
>>> import numpy as np
>>> X, y = np.ones((50, 1)), np.hstack(([0] * 45, [1] * 5))
>>> skf = StratifiedKFold(n_splits=3)
>>> for train, test in skf.split(X, y):
...     print('train -  {}   |   test -  {}'.format(
...         np.bincount(y[train]), np.bincount(y[test])))
train -  [30  3]   |   test -  [15  2]
train -  [30  3]   |   test -  [15  2]
train -  [30  4]   |   test -  [15  1]
>>> kf = KFold(n_splits=3)
>>> for train, test in kf.split(X, y):
...     print('train -  {}   |   test -  {}'.format(
...         np.bincount(y[train]), np.bincount(y[test])))
train -  [28  5]   |   test -  [17]
train -  [28  5]   |   test -  [17]
train -  [34]   |   test -  [11  5]
```

`StratifiedKFold` сохраняет соотношение классов (примерно 1 к 10) и в обучающих, и в тестовых фолдах. А у `KFold` в двух тестовых фолдах нет ни одного примера класса 1, а в третьем обучающем — ни одного примера класса 1.

`RepeatedStratifiedKFold` повторяет Stratified K-Fold n раз с разным случайным перемешиванием в каждом повторе.
